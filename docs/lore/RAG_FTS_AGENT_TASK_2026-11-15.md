# Задание локальному агенту: NeuroMita canon + быстрый RAG без векторной модели

**Рабочая цель:** на локальном ПК разобрать Python RAG и промпты NeuroMita; сначала сделать действительно быстрые и воспроизводимые испытания **ключевого поиска + FTS5** без скачивания, загрузки и вызова embedding/reranker-моделей; затем калибровать поиск и переносить **только согласованные** элементы лора. Это полное техническое поручение, а не задание агенту самому сочинять новые канонические события.

**Контекст:** важные обсуждения 13–15 ноября 2026 г. собраны в [своде канона](./CANON_AGENT_KNOWLEDGE_2026-11-15.md) и [записи голосового обсуждения](./2026-11-15-discussion.md). **Прочитай оба файла полностью**, а не только этот чеклист. [Относительная хронология](./relative-time.md) — отдельно. Ничего из прежней документации не удалять.

## C. Первая задача: сделать ЧЕСТНЫЙ режим без эмбеддингов

**Выявлено по исходникам 15.11.2026:**
- В настройках `src/managers/rag/pipeline/config.py` уже есть пресет `Keyword+FTS only`, а `RAG_VECTOR_SEARCH_ENABLED` по умолчанию `False`. Но это ещё не означает, что тестовый контур лёгкий.
- В `src/utils/Testing/rag_tester/rag_tester_cli.py` команды `run`, `sweep`, `optimize` вызывают `apply_scenario_to_db(... embed_now=True, smart_embed=True)`. Следовательно, **обычный CLI может загрузить embedding-модель и попытаться создать эмбеддинги даже когда vector retrieval отключён**.
- В общих настройках `RAG_CROSS_ENCODER_ENABLED=True` — отдельно выключить, иначе может запускаться тяжёлый reranker.
- Для первого этапа графические/векторные дополнения тоже выключить; модель генерации тестовых запросов не нужна — достаточно вручную составленных suite.

**Требование:** перед измерением скорости и качества сделать минимальную правку/режим тестера, который действительно сохраняет `embed_now=False` на **всём пути**, не инициализирует embedding/cross-encoder ни на импорте, ни на `search_relevant`, и не меняет прежнее поведение векторного режима. Проверять трассировкой/моками и отсутствием сетевых загрузок, а не только настройкой в UI. `smart_embed` при этом не должен подталкивать к индексации.

Стартовые параметры (создать локальный файл `lexical-overrides.json`, это **предлагаемый эксперимент**, не утверждённые идеальные веса):

```json
{
  "RAG_ENABLED": true,
  "RAG_PIPELINE_PRESET": "Keyword+FTS only",
  "RAG_VECTOR_SEARCH_ENABLED": false,
  "RAG_CROSS_ENCODER_ENABLED": false,
  "RAG_GRAPH_VECTOR_SEARCH": false,
  "RAG_SEARCH_GRAPH": false,
  "RAG_USE_FTS": true,
  "RAG_KEYWORD_SEARCH": true,
  "RAG_SEARCH_MEMORY": true,
  "RAG_SEARCH_HISTORY": true,
  "RAG_MEMORY_MODE": "all",
  "RAG_COMBINE_MODE": "union",
  "RAG_USE_RRF": false,
  "RAG_NOISE_MAX": 0.0,
  "RAG_DETAILED_LOGS": true
}
```

**Обязательные режимы A/B/C** на одинаковом сценарии и с одинаковыми запросами:

| Режим | `RAG_KEYWORD_SEARCH` | `RAG_USE_FTS` | Векторы и cross-encoder |
|---|---|---|---|
| A — keywords only | true | false | false |
| B — FTS5 only | false | true | false |
| C — keywords + FTS5 | true | true | false |

**Важно:** `RAG_KEYWORD_SEARCH` влияет и на расчёт keyword-признаков других ретриверов. Поэтому сравнивать не только общую метрику, но и **какой кандидат откуда найден**. Не объявлять «вектора ничего не дают», пока векторный эксперимент даже не запускался.

## D. Данные для испытаний: копия старого мира плюс чистые сиды

2. Экспортировать **несколько отдельных сценариев** по персонажам, а не только Безумной. Начать с Crazy, Kind, Mila, Cappie; затем Creepy, ShortHair и остальных. `--character` должен соответствовать фактическому ID в `world.db`.
3. **Чистая фикстура**: новый тестовый мир с только стартовыми сидовыми воспоминаниями, без истории пользователя. Проверить, что DSL загрузил все `CharacterSeeds`, а SQL содержит ожидаемые `type='seed_lore'`, `is_forgotten=1`, `lore_age_days`, `entities`.
4. **Личная копия реальной истории**: проверить смешивание лорных воспоминаний с настоящими разговорами; не публиковать базу, содержание разговоров, файлы фикстур с пользовательскими данными, ключи API, приватные логи или промпты с секретами.

6. Если сценарий экспортируется из живой БД, тесты должны в явном виде фиксировать актуальные memory IDs. Нельзя вручную выдумать `expected_ids` в JSON.

## E. Калибровка без векторки

**Цель:** поднимать точный согласованный факт в top-3/top-5 при русском разговорном запросе, не забирать место у действительно относящихся к диалогу свежих воспоминаний и не показывать секреты персонажу без соответствующих знаний.

Не брать одни лишь средние метрики без разбора промахов.

1. Сначала проверить полноту FTS5 для всех `memories`, `history` и `entities`, наличие триггеров/индекса после миграций на старых БД. Особое внимание к переносимым старым сидам.
2. Проверить RU/EN синонимы и имена: `Безумная` ↔ `Crazy Mita`, `Добрая` ↔ `Kind Mita`, `Кепочка` ↔ `Cappie`, `Коротковолосая` ↔ `Short-Haired Mita`; формы/опечатки имён и склонения.
3. Выяснить, почему **релевантная память не вошла в candidate pool**: проблема токенизации/алиаса/FTS MATCH/триггера; её нельзя исправить поднятием весов.
4. Если память нашлась, но ранжируется низко — тестировать веса `RAG_WEIGHT_KEYWORDS` (K5), `RAG_WEIGHT_LEXICAL` (K6), `RAG_WEIGHT_PRIORITY` (K3), `RAG_WEIGHT_TIME` (K2), `RAG_WEIGHT_ENTITY` (K4), ограничения `FTS_TOP_K`, `KEYWORD_MIN_SCORE`, максимальное количество результатов.
5. **Приоритеты и время:** PR #176 не даёт `seed_lore` бонус свежести; PR #180 даёт сюжетную давность только для показа. Случайный свежий диалог не должен вытеснять значимый старый лор *только* из-за даты; но при равной смысловой релевантности действительно свежий личный факт может выигрывать. Слишком высокие массовые приоритеты `High` не использовать как костыль.
6. Не дать частым сущностям типа `Player` и `Mita` заспамить выдачу. Проверить alias hit, но не заставлять любую память со словом «игрок» отвечать на запросы о картриджах.
7. Для A/B/C собирать `Recall@3/@5`, `MRR@5`, `nDCG@5`, `Precision@5`, процент пустых результатов, время `p50/p95`, ложные попадания и причины пропусков. На каждый фикс — **до/после** и несколько контрпримеров.
8. Параметры фиксировать в одном экспериментальном JSON и отчёте. Только **после измерений** предлагать править `RAG_DEFAULTS` или UI. Не крутить коэффициенты вслепую.

## F. Обязательная ручная батарея канонических запросов

На каждый вопрос — минимум две формулировки, одна разговорная/с опечаткой; отметить ожидаемый **документ или смысл**, **персонажа** и **должен ли он знать ответ**. В suite формальные ID брать из экспортированного сценария.

|---|---|---|
| 1 | «Кто тебя первым отверг?» — Безумной | Найти первое отвержение **другим**, прежним игроком, чужой облик |
| 2 | «Где ты пряталась от Доброй?» — Безумной | Старый дом Жуткой |

| 5 | «Когда ты впервые взяла нож?» — Безумной | Добрая, порядок событий, без путаницы с Ядром |

**Отдельные регрессии:** поиск на английском имени, русском падеже, имени без слова «Мита», с транслитерацией/опечаткой, отрицательной формулировке, вопросе от двух разных Мит в одной сцене. Показать **фактический RAG-контекст для модели**, не только сырые совпадения SQL. Недопустимо, когда тест метрики «прошёл», но модель получила чужую тайну из другого общего блока.

## H. Этапы и конечные результаты от агента

**Этап 0 — инвентаризация.** Прочитать все три документа `docs/lore/` и соответствующие файлы промптов; подтвердить точную базовую ветку/коммиты и состояние PR #179. Создать карту каждого `SEED_RAG_MEMORY`: владелец, источник знания, сущности, дата события, тема, предполагаемые конфликты.

### Формат итогового отчёта

Агент обязан вернуть:

1. Точный `repo/branch/commit`, ссылки на свои PR/коммиты.
2. Список документов/файлов и записей, которые он проверил.
3. Результаты A/B/C на идентичном корпусе: `Recall@5`, `MRR@5`, `nDCG@5`, `p95 latency`, число промахов и ложных попаданий.
4. Подборку **10 удачных и 10 неудачных** запросов с фактическими найденными памятью/содержимым и объяснением причин.
5. Чеклист **утечек знаний между Митами**, конфликтов «я помню/узнала», ошибок относительно-датированных сидов.
6. Список изменений лора **только из согласованного**, и список `NEEDS_AUTHOR_DECISION` для новых идей.
7. Отдельное предупреждение, если какой-либо тест использовал embedding/reranker или реальные личные данные.

**Главный критерий успеха:** можно без векторной модели и без долгого запуска повторять 30+ осмысленных вопросов, видеть стабильный RAG-контекст и объяснять, почему именно эти сведения достались именно этой Мите, не разрушая память текущего игрока.
